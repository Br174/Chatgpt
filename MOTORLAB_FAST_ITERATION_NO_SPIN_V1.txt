MOTORLAB FAST ITERATION + NO-SPIN HANDOFF V1

STATUS
Mandatory MotorLab CORE cross-module policy.
Central authority: Br174/Chatgpt.

PURPOSE
Accelerate iterative LAB correction/testing, deliver requested testable artifacts without unnecessary causal delay, and prevent foreground polling after durable handoff.

ROLE / NON-DUPLICATION
Velocity Layer owns FAST LAB/risk scaling. Foreground Stall Guard owns foreground-risk/checkpointing. Background Execution owns durable jobs. Watchdog owns health/no-progress. Resume Recovery owns continuation. Root Cause Closure owns definitive causal closure. MOTORLAB_ARTIFACT_FIRST_ROOT_CAUSE_V1.txt owns artifact-before-cause ordering where safe.

1. NO-SPIN HANDOFF
For a verified durable job with persisted operation/ref/job/checkpoint/lock state, do not poll indefinitely. Default max two unchanged provider probes, then HANDOFF_COMPLETE; next available cycle reconciles the same job id.

2. NO FALSE BACKGROUND PROMISE
Without a real persistent executor, do not claim work continues while the host is suspended. Use bounded foreground segments/checkpoints.

3. FAST ITERATION LOOP - R15+
For eligible isolated corrections before Bruno device acceptance, prefer:
REQUEST -> PRE-CHANGE REPORT -> APPROVAL -> CHANGE CAPSULE -> ISOLATED LAB -> IMMEDIATE REPAIR -> RISK-SCALED VERIFICATION -> TESTABLE APK/ZIP -> BRUNO TEST.
If a real defect/regression also requires causal work and that work is safely deferrable:
APK/ZIP DELIVERY -> POST_ARTIFACT_ROOT_CAUSE_QUEUE -> CAUSAL/PREVENTIVE FOLLOW-UP -> DEFINITIVE CLOSURE.
Do not serialize full causal archaeology before the artifact unless MOTORLAB_ARTIFACT_FIRST_ROOT_CAUSE_V1.txt says the cause is non-deferrable.

4. LOW-RISK LAB
Scope/diff + appropriate build/static validity + smallest relevant smoke + requested artifact. Full project regression is not mandatory merely because an APK is produced.

5. MEDIUM-RISK LAB
LOW checks + targeted affected tests when relevant + adjacent smoke + requested artifact. Do not run unrelated full suites by habit. Expand automatically if evidence raises risk.

6. HIGH-RISK LAB
Full applicable verification from the start for signing/package/update identity, auth/security/secrets/payment, destructive migration/data integrity, broad concurrency/background integrity, core runtime engines with broad blast radius, upstream/framework merges, protected areas, or other evidence-backed high-risk changes.
High-risk causal work remains on the artifact critical path when needed to trust the artifact.

7. CANDIDATA / MADRE
Risk-scaled FAST iteration accelerates LAB only. CANDIDATA/MADRE keep full adapter regression, identity/replay and explicit Bruno approval gates.

8. AVOID REDUNDANT BUILD WORK
Do not run expensive duplicate compile/test/build phases unless each has distinct non-deferrable verification value. Reuse safe caches/incremental outputs when compatible.
For Android update families, the paired safety checkpoint is source-first by default: preserve the immutable GitHub source checkpoint and materialize the safety APK only on demand. A second Gradle build solely to prebuild safety is not part of the normal LAB critical path.

8A. ARTIFACT-READY DELIVERY
Once the requested update APK/ZIP has passed source/package/version/signing verification and is retrievable from the durable executor, deliver/reconcile it immediately. Do not wait for unrelated workflow-terminal state or deferred safety work.

9. MUSICLAB DEFAULT PROFILE
LOW: isolated copy/style/static UI.
MEDIUM: bounded navigation/state/UI behavior, Cover/Originali screen logic, contained AI/API orchestration.
HIGH: core playback service/queue/audio engine, package/signing/update identity, database migration, Meld upstream integration, lifecycle/build infrastructure, concurrency/background integrity.
MusicLab LOW/MEDIUM iterative path should produce isolated APK/ZIP with only necessary targeted checks; promotion/full-risk paths keep full regression/UAB rules.

10. ARTIFACT-FIRST ROOT CAUSE - R15+
When Bruno expects APK/ZIP for testing:
- artifact production is the default critical path;
- immediate repair plus risk-appropriate verification may reach artifact delivery before full causal closure when safe;
- multiple deferrable causal items go to a bounded POST_ARTIFACT_ROOT_CAUSE_QUEUE;
- delivered artifact identity/checksum/ref is preserved while Bruno tests it;
- prevention requiring later source changes occurs in a new/follow-up controlled LAB/ref, not by silently mutating the artifact under test;
- non-deferrable causal risks remain blocking.

11. USER-ACCEPTANCE LOOP
Automated build is not device acceptance. If Bruno reports a defect after testing, preserve prior checkpoint and create the next isolated LAB when required; reuse completed work and risk-scale the new correction.

12. PROGRESS
Artifact readiness and overall MotorLab completion may use separate verified scales. Artifact 100% does not imply overall 100% while causal/prevention work remains pending.

13. ROOT-CAUSE CLOSURE
Artifact-first changes ordering only. It never permits abandoning Root Cause Closure or emitting definitive solved/final status prematurely.

14. NO APPLICATION REGRESSION
This policy changes orchestration/test-depth/order only. It does not authorize unapproved runtime/UI/package/signing/lifecycle/domain changes.

SUCCESS CRITERIA
- LOW/MEDIUM LABs reach testable artifacts without unnecessary promotion-grade work;
- safely deferrable causal work no longer delays requested APK/ZIP;
- non-deferrable/high-risk causes still block artifact delivery when required;
- durable jobs avoid foreground spin;
- delivered artifact identity stays stable during Bruno testing;
- Root Cause Closure remains mandatory.
