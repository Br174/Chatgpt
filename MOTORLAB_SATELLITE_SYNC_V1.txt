MOTORLAB SATELLITE SYNC V1

STATUS
Mandatory MotorLab synchronization capability.
Central authority: Br174/Chatgpt.

PURPOSE
Keep one verified local MotorLab satellite per registered project while Br174/Chatgpt remains authoritative, with safe release adoption and no silent loss of newer CORE gates.

BOOT
1. Read `.motorlab/MOTORLAB_BOOT_CAPSULE.txt` first, then project hook + local sync/core.
2. Use VERIFIED local core immediately as fallback.
3. When central is reachable, read release manifest and compare releases.
4. Reconcile Project Continuity/live state before selecting a safe update boundary.
5. Load all release-required capabilities, including r12 Fast Iteration/No-Spin, r13 technical Change History, r14 Pre-Change Approval + visible restore register, r15 Artifact-First + deferred Root Cause, r16 Authority/Data Ownership + Persistent Operational State + Observability + Knowledge Tool Routing + Service Integration Status, r20 Pollicino continuity, r21 Four-Pillar adaptive Velocity/TTTA/learning semantics, r22 operational Execution Fabric dispatch/proof semantics, r23 incremental dynamic work-elimination/event-memory semantics and r32 Build Fast Lane/deferred safety materialization.

SAFE UPDATE
- pin one MotorLab release during active write/build/test/promotion;
- adopt newer release only at a verified safe boundary;
- preserve current VERIFIED bundle as LAST_GOOD;
- fetch/validate MOTORLAB_BOOT_CAPSULE_V1.txt and MOTORLAB_SATELLITE_BUNDLE_V1.txt release id + required markers;
- write the central capsule to `.motorlab/MOTORLAB_BOOT_CAPSULE.txt` before declaring adoption complete;
- replace only MotorLab control-plane files;
- use safe CI suppression for metadata-only synchronization where supported;
- never suppress validation when real app/source/config changes share the commit;
- update sync state/hook as needed;
- re-read local files before declaring adoption complete;
- write through central continuity/integration state so adoption cannot remain silently stale.

R23+ INCREMENTAL DYNAMIC EXECUTION
Local fallback must preserve:
- safe reuse/cache before new execution;
- content-addressed correctness identities with explicit invalidation;
- delta-scoped recomputation;
- critical-path-first allocation after work elimination;
- runtime DAG growth from discoveries without operation restart;
- FAST LINE -> MINI TREE -> FULL DYNAMIC GRAPH progressive escalation;
- safe pending-task pruning;
- material event-memory persistence through existing operational state;
- deferred materialization of unnecessary intermediates;
- proof of cache hits/avoided work/dynamic branches/pruning when observable.
Cache is never technical authority and cannot bypass current-source/freshness/safety gates.

R22+ EXECUTION FABRIC
Local fallback must preserve:
- Velocity as sole scheduler and Execution Fabric as subordinate dispatcher;
- DIRECT_FAST for trivial deterministic work;
- event-driven READY-queue dispatch for eligible operations;
- same-cycle batching of independent tool/read calls when the host supports it;
- concurrent durable nodes through Background Execution when useful;
- no unnecessary global barriers;
- write-scope collision prevention + one final integration lane;
- correction relay preserving unaffected work;
- observed parallelism proof rather than configuration-only claims;
- truthful SERIAL_HOST_LIMITED mode;
- grouped runner status rather than one-step-at-a-time narration.
If the local executor cannot host the reference dispatcher directly, it must implement equivalent semantics through its native parallel tool/job mechanism and report proof level honestly.

R21+ FOUR PILLARS / ADAPTIVE VELOCITY

- adapt runner count to expected net speedup rather than maximizing concurrency;
- isolate parallel writes and keep one final integration lane;
- converge continuously and correct only affected scopes;
- reuse valid incremental/cached/test/research evidence;
- preserve bounded context-aware lessons from verified errors/research/timings/experience;
- never let lessons or speed bypass approval, compatibility, current technical truth, single-writer or promotion gates.
