MOTORLAB SATELLITE SYNC V1

STATUS
Mandatory MotorLab synchronization capability.
Established: 2026-09-29.
Central authority: Br174/Chatgpt.

PURPOSE
Each registered project keeps a verified local MotorLab satellite while Br174/Chatgpt remains the single authoritative MotorLab source.

BOOT
1. Read project MOTORLAB_PROJECT_HOOK.txt.
2. Read .motorlab/MOTORLAB_SYNC_STATE.txt.
3. Read .motorlab/MOTORLAB_LOCAL_CORE.txt.
4. Verified local core is immediately available as fallback.
5. When central is reachable, read MOTORLAB_RELEASE_MANIFEST_V1.txt and compare local/central releases.
6. Resolve the project-specific Project Continuity ledger pointer and reconcile current state before choosing a work starting point.

SAFE UPDATE
- pin a MotorLab release for the whole active operation;
- never update during active write/build/test/promotion/release;
- update only at a safe boundary;
- preserve current verified local bundle as LAST_GOOD before adopting newer bundle;
- fetch MOTORLAB_SATELLITE_BUNDLE_V1.txt;
- validate release id and required markers;
- replace only MotorLab control-plane files;
- update sync state;
- re-read local files and verify before declaring success.

It must also preserve:
- classic `Progresso MotorLab: <N>%` format;
- high presence of the current verified percentage on meaningful substantial operational statuses once a verified value exists;
- same-percentage repetition when state changes without new verified progress;
- no fabricated percentage advancement;
- distinction between 🐢 slow-but-live, ⏳ legitimate external wait and ⚡ actual recovery/health action;
- no hidden chain-of-thought disclosure under 💭.

ROLLBACK
If newer bundle cannot be verified, keep/restore LAST_GOOD, preserve project and report fallback.

CENTRAL UNAVAILABLE
Use previously VERIFIED local release plus live repository/provider evidence. Do not invent continuity state. Recheck central at a later safe cycle.

NO APP RUNTIME CHANGE
.motorlab is development/orchestration metadata and must not intentionally alter app code, UI, package identity, signing, native engines or runtime dependencies.

FUTURE PROJECTS
Future MotorLab software projects receive hook + local satellite + central Project Continuity ledger during onboarding and inherit current visual/progress rules.

AUTOMATIC MEANING
Synchronization/continuity writes occur only when an execution cycle with repository access exists. Repository text cannot self-update or wake a frozen host without an executor.
