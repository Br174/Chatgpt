MOTORLAB SATELLITE SYNC V1

STATUS
Mandatory MotorLab synchronization capability.
Central authority: Br174/Chatgpt.

PURPOSE
Keep one verified local MotorLab satellite per registered project while Br174/Chatgpt remains authoritative, with safe release adoption and no silent loss of newer CORE gates.

BOOT
1. Read project hook + local sync/core.
2. Use VERIFIED local core immediately as fallback.
3. When central is reachable, read release manifest and compare releases.
4. Reconcile Project Continuity/live state before selecting a safe update boundary.
5. Load all release-required capabilities, including r12 Fast Iteration/No-Spin, r13 technical Change History, r14 Pre-Change Approval + visible restore register, and r15 Artifact-First + deferred Root Cause.

SAFE UPDATE
- pin one MotorLab release during active write/build/test/promotion;
- adopt newer release only at a verified safe boundary;
- preserve current VERIFIED bundle as LAST_GOOD;
- fetch/validate MOTORLAB_SATELLITE_BUNDLE_V1.txt release id + required markers;
- replace only MotorLab control-plane files;
- use safe CI suppression for metadata-only synchronization where supported;
- never suppress validation when real app/source/config changes share the commit;
- update sync state/hook as needed;
- re-read local files before declaring adoption complete;
- write through central continuity/integration state so adoption cannot remain silently stale.

R15+ ARTIFACT-FIRST
When Bruno requests APK/ZIP/testable artifacts for approved defect/regression work, the local fallback must preserve:
- repair/verify/artifact/deliver as default critical path;
- safely deferrable causal work in durable POST_ARTIFACT_ROOT_CAUSE_QUEUE;
- non-deferrable high-risk causal work before delivery when needed to trust artifact;
- separate artifact vs overall progress;
- exact delivered artifact/ref/checksum preserved during Bruno testing;
- no definitive solved/final status while causal work remains pending.

R14+ HARD APPROVAL / VISIBLE RESTORE
Initial mutation wording is intent only. Show pre-change report and wait for Bruno approval before first write. Visible restore slots contain only specific Bruno-confirmed working modifications using stable plain integers.

R13+ TECHNICAL HISTORY
Technical Change History is Git-backed provenance/search and remains distinct from the visible restore register.

R12+ FAST ITERATION / NO-SPIN
Eligible LOW/MEDIUM isolated LAB iteration may use risk-scaled checks. HIGH-risk and CANDIDATA/MADRE retain full gates. Durable executor handoff must not cause indefinite foreground polling.

ROLLBACK
If newer bundle cannot be verified, keep/restore LAST_GOOD and preserve project state.

CENTRAL UNAVAILABLE
Use previously VERIFIED local release plus live evidence conservatively; do not invent newer rules as locally installed.

FUTURE PROJECTS
Future projects receive hook + local satellite + Project Continuity + technical history + visible restore register and inherit current release gates.

AUTOMATIC MEANING
Synchronization requires an execution cycle with repository access; repository text cannot self-update or wake a frozen host.

NO APP RUNTIME CHANGE
MotorLab metadata must not intentionally alter app code/UI/package/signing/native engines/runtime dependencies.
