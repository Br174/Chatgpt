MOTORLAB SATELLITE SYNC V1

STATUS
Mandatory MotorLab synchronization capability.
Central authority: Br174/Chatgpt.

PURPOSE
Keep one verified local MotorLab satellite per registered project while Br174/Chatgpt remains authoritative, with safe release adoption and no silent loss of newer CORE gates.

BOOT
1. Read project hook + local sync/core.
2. Use VERIFIED local core immediately as fallback.
3. When central is reachable, read release manifest and compare releases.
4. Reconcile Project Continuity/live state before selecting a safe update boundary.
5. Load all release-required capabilities, including r12 Fast Iteration/No-Spin, r13 technical Change History, r14 Pre-Change Approval + visible restore register, r15 Artifact-First + deferred Root Cause, and r16 Authority/Data Ownership + Persistent Operational State + Observability + Knowledge Tool Routing + Service Integration Status.

SAFE UPDATE
- pin one MotorLab release during active write/build/test/promotion;
- adopt newer release only at a verified safe boundary;
- preserve current VERIFIED bundle as LAST_GOOD;
- fetch/validate MOTORLAB_SATELLITE_BUNDLE_V1.txt release id + required markers;
- replace only MotorLab control-plane files;
- use safe CI suppression for metadata-only synchronization where supported;
- never suppress validation when real app/source/config changes share the commit;
- update sync state/hook as needed;
- re-read local files before declaring adoption complete;
- write through central continuity/integration state so adoption cannot remain silently stale.

R19+ FOUNDATIONAL CHANGE COMPATIBILITY PILLAR
Local fallback must preserve mandatory pre-write overlap/redundancy/conflict preflight for every MotorLab/project modification. ONE RESPONSIBILITY = ONE ACTIVE COORDINATOR. Existing equivalent logic must be reused/extended/merged or explicitly superseded; do not stack competing paths.

R18+ PAIRED SAFETY LAB
Local fallback must pair every verified LAB NN aggiornamento with immutable LAB di sicurezza NN from the same functional source state, using a distinct package/family and unique test-only signing certificate. Preserve safety checkpoint provenance for recovery into a new active family.

R17+ ANDROID UPDATE FAMILY
Local fallback must preserve MOTORLAB_UPDATE_FAMILY_LIFECYCLE_V1.txt when update-family mode is enabled: stable same-family package/signing identity, increasing versionCode, Bruno-facing LAB NN aggiornamento names, new-family immutable CANDIDATA creation and same-candidate CANDIDATA->MADRE promotion.

R16+ AUTHORITY / PERSISTENT STATE / TOOL ROUTING
Local fallback must preserve:
- GitHub technical authority;
- D1 live operational authority only when actually connected and reconciled;
- KV cache-only status;
- one MOTORLAB_OPERATION_ID per logical operation;
- PostHog evidence-only role;
- Notion/GitBook projection-only roles;
- Superpowers subordinate methodology;
- Context7 targeted on-demand documentation;
- graceful degradation and no hidden paid fallback;
- explicit CORE_READY vs CONNECTED_VERIFIED/RESOURCE_READY/PROJECT_ADOPTED status from MOTORLAB_SERVICE_INTEGRATION_STATUS_V1.txt.
Local r16 adoption does NOT mean optional provider/plugin connections are active; capability status must be verified separately.

R15+ ARTIFACT-FIRST
When Bruno requests APK/ZIP/testable artifacts for approved defect/regression work, the local fallback must preserve:
- repair/verify/artifact/deliver as default critical path;
- safely deferrable causal work in durable POST_ARTIFACT_ROOT_CAUSE_QUEUE;
- non-deferrable high-risk causal work before delivery when needed to trust artifact;
- separate artifact vs overall progress;
- exact delivered artifact/ref/checksum preserved during Bruno testing;
- no definitive solved/final status while causal work remains pending.

R14+ HARD APPROVAL / VISIBLE RESTORE
Initial mutation wording is intent only. Show pre-change report and wait for Bruno approval before first write. Visible restore slots contain only specific Bruno-confirmed working modifications using stable plain integers.

R13+ TECHNICAL HISTORY
Technical Change History is Git-backed provenance/search and remains distinct from the visible restore register.

R12+ FAST ITERATION / NO-SPIN
Eligible LOW/MEDIUM isolated LAB iteration may use risk-scaled checks. HIGH-risk and CANDIDATA/MADRE retain full gates. Durable executor handoff must not cause indefinite foreground polling.

ROLLBACK
If newer bundle cannot be verified, keep/restore LAST_GOOD and preserve project state.

CENTRAL UNAVAILABLE
Use previously VERIFIED local release plus live evidence conservatively; do not invent newer rules as locally installed.
Optional service state must not override verified local/GitHub technical evidence.

FUTURE PROJECTS
Future projects receive hook + local satellite + Project Continuity + technical history + visible restore register and inherit current release gates.

AUTOMATIC MEANING
Synchronization requires an execution cycle with repository access; repository text cannot self-update or wake a frozen host.

NO APP RUNTIME CHANGE
MotorLab metadata must not intentionally alter app code/UI/package/signing/native engines/runtime dependencies. Telemetry SDKs and service bindings remain project changes requiring normal approval.

R20+ POLLICINO CONTINUITY
Local fallback must preserve the external-only Pollicino contract: supported liveness + progress fingerprint evidence, terminal seals, compact session journal and precomputed RESUME_READY.
Do not place heartbeat/breadcrumb logic in application runtime code merely for MotorLab continuity.
Watchdog/Resume ownership and single-writer precedence remain unchanged.
When the local executor supports Codex hooks, sync the external Pollicino sidecar/hook template at a safe boundary; never place it in application runtime source.
For a private adopted satellite using source-proof enrollment, publish/update `POLLICINO_PROOF_HEAD=<current adopted Git SHA>` in D1 at the same verified adoption boundary; do not rely exclusively on mutable project operational heads.
