MOTORLAB SATELLITE SYNC V1

STATUS
Mandatory MotorLab synchronization capability.
Established: 2026-09-29.
Central authority: Br174/Chatgpt.

PURPOSE
Each registered project keeps a verified local MotorLab satellite while Br174/Chatgpt remains the single authoritative MotorLab source.

BOOT
1. Read project MOTORLAB_PROJECT_HOOK.txt.
2. Read .motorlab/MOTORLAB_SYNC_STATE.txt.
3. Read .motorlab/MOTORLAB_LOCAL_CORE.txt.
4. Verified local core is immediately available as fallback.
5. When central is reachable, read MOTORLAB_RELEASE_MANIFEST_V1.txt and compare local/central releases.
6. Resolve the project-specific Project Continuity ledger pointer from hook/registry and reconcile state before choosing a work starting point.

SAFE UPDATE
- pin a MotorLab release for the whole active operation;
- never update during active write/build/test/promotion/release;
- update only at safe boundary;
- preserve current verified local bundle as LAST_GOOD before adopting newer bundle;
- fetch MOTORLAB_SATELLITE_BUNDLE_V1.txt;
- validate release id and required markers;
- replace only MotorLab control-plane files;
- update sync state;
- re-read local files and verify before declaring success.

A valid r8+ local fallback must preserve these rules:
- recognized project/software-build activation occurs before substantive work;
- first user-visible line is the MotorLab banner;
- each project hook points to a central Project Continuity ledger;
- new chats reconcile ledger + newer live repo/provider/job/artifact state;
- unfinished work continues under Resume Recovery/Watchdog without transfer prompts;
- continuation-relevant material state writes through to the central ledger when safe;
- older registries/memory cannot override newer coherent state.

ROLLBACK
If newer bundle cannot be verified, keep/restore LAST_GOOD, record safe failure, preserve project and report fallback.

CENTRAL UNAVAILABLE
Use previously VERIFIED local release plus live repository/provider evidence. Do not invent continuity state. Recheck central at a later safe cycle.

NO APP RUNTIME CHANGE
.motorlab is development/orchestration metadata and must not intentionally alter app code, UI, package identity, signing, native engines or runtime dependencies.

FUTURE PROJECTS
Future MotorLab software projects receive hook + local satellite + central Project Continuity ledger during onboarding when technically available.

AUTOMATIC MEANING
Synchronization/continuity writes occur when an execution cycle with repository access exists. Repository text cannot self-update or wake a frozen host without an executor.
