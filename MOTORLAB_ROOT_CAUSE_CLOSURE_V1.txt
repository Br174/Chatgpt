MOTORLAB ROOT CAUSE CLOSURE V1 - SYMPTOM + CAUSE + PREVENTION GATE

STATUS
Mandatory MotorLab CORE capability.
Central authority: Br174/Chatgpt.

PURPOSE
Ensure that defects are not treated as definitively solved merely because the visible symptom was corrected, while allowing a requested testable artifact to be delivered before full causal closure when deferral is safe under MOTORLAB_ARTIFACT_FIRST_ROOT_CAUSE_V1.txt.

CORE PRINCIPLE
FIX THE SYMPTOM, DELIVER THE SAFE TEST ARTIFACT WHEN REQUESTED, FIND THE CAUSE, PREVENT THE RECURRENCE.
Artifact delivery can precede causal closure; definitive problem closure cannot.

1. MANDATORY TWO-TRACK RESPONSE
For every concrete defect, anomaly, stale state, failed build/test, unexpected trigger, synchronization miss, regression or repeatable operational problem, MotorLab runs both tracks:
A. CONTAINMENT / IMMEDIATE REPAIR
- preserve valid work;
- correct or safely contain the immediate symptom;
- restore the requested usable/testable behavior when possible.
B. ROOT-CAUSE / PREVENTION
- determine why the symptom occurred;
- identify failed mechanism, missing trigger, stale state, race, configuration gap, dependency/provider failure or external prerequisite;
- correct/contain the causal mechanism when safe;
- inspect the relevant recurrence surface;
- add proportionate prevention/regression protection.

TRACK ORDERING - R15+
When Bruno requested APK/ZIP/testable artifact, Track A plus risk-appropriate artifact verification is the default critical path. Track B may continue AFTER artifact delivery when MOTORLAB_ARTIFACT_FIRST_ROOT_CAUSE_V1.txt classifies it as safely deferrable. This changes ordering, never the obligation to complete Track B.

2. CLOSURE STATES
Useful internal states:
- SYMPTOM_PRESENT
- SYMPTOM_CONTAINED
- ARTIFACT_READY_CAUSE_PENDING
- ARTIFACT_DELIVERED_CAUSE_PENDING
- ROOT_CAUSE_UNDER_INVESTIGATION
- ROOT_CAUSE_CONFIRMED
- ROOT_CAUSE_CORRECTED
- PREVENTION_VERIFIED
- CLOSED_VERIFIED
Do not mark CLOSED_VERIFIED until immediate correction plus required causal/prevention handling are complete or honestly blocked by unavailable external evidence/permission.

3. USER-FACING STATUS RULE
`✅ Problema risolto` remains reserved for verified symptom correction plus causal mechanism corrected/prevented, or proven external/non-controllable cause with verified containment/fallback and explicit limitation.
If artifact is ready while cause remains pending, do NOT use definitive solved status. Prefer:
`🎆 Azione completata — APK/ZIP pronto e verificato per il test; la chiusura causale continua.`
with separate artifact and overall progress when useful.

4. ROOT-CAUSE EVIDENCE
Distinguish CONFIRMED_CAUSE, LEADING_HYPOTHESIS, EXTERNAL_CAUSE and UNKNOWN_CAUSE. Never present a hypothesis as fact.

5. RECURRENCE-SURFACE CHECK
After a cause is confirmed, inspect the smallest relevant blast radius: sibling workflows/triggers, related branches/lifecycle stages, adapters/satellites, repeated write paths, equivalent jobs and future onboarding defaults when materially exposed. Avoid unbounded rewrites.

6. PREVENTION OPTIONS
Use the least invasive effective prevention: filters, invariants, reconciliation/write-through rules, regression tests, validation gates, idempotency/single-writer guards, bounded retries/change-of-strategy, or explicit external fallback/blocker state.

7. PROJECT CONTINUITY INTEGRATION
If a continuity ledger is stale when an update was expected, reconcile from newer live evidence, then investigate and correct the missed write-through path. Manual refresh alone is not causal closure.
Control-plane-only events must not silently become new application lifecycle operations.

8. WATCHDOG / RECOVERY INTEGRATION
Watchdog may detect symptoms; Resume Recovery may restore work; Root Cause Closure owns definitive closure. A successful retry/restart/recovery alone is not proof the underlying cause is removed.

9. CHANGE COMPATIBILITY / APPROVAL
Before causal/preventive writes apply Change Compatibility Guard and the current Pre-Change Approval scope. If post-artifact investigation requires a materially broader behavior/component than approved, obtain amended approval before that broadened write. Read-only causal analysis may continue.

10. PROGRESS REPORTING - R15+
Root-cause work remains part of the overall requested problem-solving operation, but no longer necessarily part of the artifact-delivery subscale.
Allowed reporting:
- ARTIFACT_PROGRESS may reach 100% when the requested artifact is built, risk-appropriately verified and delivered;
- MOTORLAB_OVERALL_PROGRESS remains below 100% while mandatory causal/prevention work remains pending.
Do not use overall 100%, `✅ Problema risolto`, or `💯 Conclusione definitiva` merely because the artifact was delivered.

11. DEFERRED ROOT-CAUSE QUEUE
When causal work is safely deferred, persist a bounded POST_ARTIFACT_ROOT_CAUSE_QUEUE with each pending defect, immediate repair, delivered artifact/ref/checksum, evidence/cause status, relevant recurrence surfaces and next causal/prevention step. Process the queue after artifact delivery during available execution cycles or a real durable executor.

12. NON-DEFERRABLE ROOT CAUSE
MOTORLAB_ARTIFACT_FIRST_ROOT_CAUSE_V1.txt controls cases where cause/prevention must remain on the artifact critical path, including material safety/security/signing/data-integrity/unreliable-build risks or where symptom-only containment cannot establish a trustworthy artifact.

13. BOUNDED INVESTIGATION
Stop expanding when the cause is confirmed and relevant recurrence surface is protected, the cause is proven external with verified fallback, or further work is blocked by unavailable evidence/permission. Do not create endless speculative searches.

14. CURRENT/FUTURE PROJECT RULE
Global across all current/future MotorLab-managed software projects. Project-native engines remain authoritative for domain behavior.

15. NO FALSE CLOSURE
Not sufficient alone for definitive closure: one successful retry, manual stale-file refresh, rerun build, alternate provider, restart, visually correct output, or artifact delivery while causal work remains pending.

SUCCESS CRITERIA
- immediate repairs reach testable artifacts quickly when safe;
- safely deferrable causal work no longer blocks artifact delivery;
- causal/prevention work remains mandatory and durable;
- high-risk/non-deferrable causes still block artifact delivery when required for trust;
- definitive problem/final completion statuses are not emitted prematurely.
