MOTORLAB RESUME RECOVERY V1 - POST-TOOL CONTINUATION + NEXT-CYCLE RECOVERY

STATUS
Mandatory MotorLab CORE capability.
Established: 2026-09-29.
Repository authority: Br174/Chatgpt.

PURPOSE
Prevent a MotorLab-controlled task from appearing to stop after a tool/build/API/GitHub response when requested work is incomplete, and guarantee deterministic recovery at the first execution cycle available after host/model interruption.

ROLE / PRECEDENCE
Resume Recovery owns continuation from checkpoint/pending-action state.
MOTORLAB_WATCHDOG_V1.txt owns health detection, anti-loop decisions and recovery level.
MOTORLAB_FOREGROUND_STALL_GUARD_V1.txt owns prevention before risky foreground work.
Resume Recovery must not independently start a competing second recovery path for the same operation.

1. POST-TOOL CONTINUATION GUARD - MANDATORY
After every tool/provider/build/GitHub/API response, immediately evaluate whether the user task is complete.
If NOT complete and execution control remains, continue the same turn with the next safe action.
A tool result is intermediate unless it satisfies the request or establishes a genuine blocker.

2. VALID TURN TERMINATION STATES
A controlled turn may finish only in:
- COMPLETED;
- BLOCKED_EXTERNAL;
- BLOCKED_USER;
- SAFE_STOP;
- HANDOFF_COMPLETE.
It is not valid to end merely because a tool returned, a repository read finished, an intermediate percentage was shown or the assistant forgot the next step.

3. PENDING-ACTION LEDGER
For substantial tasks maintain when possible:
- operation_id;
- current phase;
- completed step;
- exact next safe step;
- pending verification;
- checkpoint_id;
- last verified progress percentage;
- write lock scope;
- Watchdog recovery level;
- same_strategy_no_progress_count when relevant.
Before ending, verify that no approved safe action remains pending.

4. SAME-TURN RESUME
If a tool response arrives and the task is incomplete:
A. update fingerprint/checkpoint if materially changed;
B. perform the next safe action;
C. continue until a valid terminal state;
D. emit useful operational progress according to MOTORLAB_PROGRESS_REPORTING_V1.txt.
Do not ask Bruno to say "continua" merely to resume a known safe pending action.

5. NEXT-AVAILABLE-CYCLE RECOVERY
If model/host/client interrupts execution so same-turn continuation cannot occur, the first later execution cycle with access to state must:
- detect the unfinished operation when state is available;
- restore latest verified checkpoint/pending ledger;
- preserve last verified percentage;
- verify current external/provider/repository state before writing;
- ask Watchdog to classify current health/recovery level;
- resume only the smallest safe pending substep;
- avoid duplicating completed work;
- preserve single-writer locking;
- visibly report recovery with lightning when a real recovery is performed.

Default visible format:
⚡ Ripresa MotorLab — riprendo dal checkpoint <id>/<fase> preservando il lavoro già verificato.

6. MANUAL `⚡` RECOVERY OPPORTUNITY - HIGH PRIORITY
When Bruno sends a message consisting only or primarily of `⚡`, treat that message as an explicit request to inspect and resume the current MotorLab operation at the first available execution cycle.
Do not reinterpret the whole project request from zero.
Procedure:
A. look for active/pending operation and latest checkpoint;
B. inspect current provider/job/repository state;
C. preserve completed work and percentage;
D. preserve lock/single-writer safety;
E. invoke Watchdog health classification;
F. if stalled/interrupted, continue from the exact next safe step;
G. if healthy external work is still running, report that state and do not duplicate it;
H. if no pending operation exists, report that no recoverable pending task was found instead of inventing one.

The manual `⚡` command is a shortcut/fallback, not a prerequisite. Automatic same-turn and next-cycle recovery remain mandatory.
If the host/client is fully suspended and does not deliver the message, `⚡` cannot create an execution cycle by itself.

7. USER MESSAGE AS RECOVERY OPPORTUNITY, NOT REQUIREMENT
Messages such as "ti sei bloccato", "continua", `⚡` or another follow-up may provide the first available execution cycle and trigger recovery.
The architecture must not treat a user message as logically required for correctness.

8. TWO-STRIKE INTEGRATION
Resume Recovery must honor Watchdog's Two-Strike No-Progress Rule.
If the same recovery/action strategy has already failed to create material progress twice without new evidence, Resume Recovery must not execute a third materially identical attempt.
It must instead follow Watchdog's changed-strategy/diagnosis/safe-stop decision.
Legitimate read-only status checks of a healthy long-running job are not failed recovery attempts.

9. NO FALSE AUTONOMY CLAIM
MotorLab cannot independently wake a completely frozen ChatGPT client/model turn when the host exposes no execution cycle, heartbeat, callback, durable job or automation trigger.
Where a durable async job/Work/worker exists, use its real capabilities; otherwise recovery occurs at first available assistant execution cycle.

10. WATCHDOG INTEGRATION
- Watchdog owns detection/intervention level;
- unchanged external state uses Watchdog fingerprints/adaptive thresholds;
- recovery never creates a second writer;
- retries remain targeted/bounded;
- Watchdog Level 4 safe-stop remains authoritative.

11. PROJECT-WIDE SCOPE
This capability applies automatically to every current/future MotorLab-managed software project through shared CORE and synchronized satellite behavior.

12. BOOTSTRAP REQUIREMENT
MOTORLAB_AUTO_BOOTSTRAP_V1.txt must load this module for recognized projects and intent-activated future software projects.

13. SUCCESS CRITERIA
Resume Recovery is active when:
- tool results cannot silently terminate incomplete work while execution control remains available;
- next safe action is explicit for substantial work;
- interruptions recover at first available cycle from latest verified checkpoint;
- manual `⚡` can request immediate checkpoint/status recovery without restarting from zero;
- automatic recovery does not depend on Bruno sending `⚡`;
- Watchdog two-strike strategy decisions are obeyed;
- no completed work is repeated unnecessarily;
- no second writer is created;
- no false claim is made about awakening a host with no execution cycle.
