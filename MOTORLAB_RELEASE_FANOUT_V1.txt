MOTORLAB RELEASE FANOUT V1

STATUS
Mandatory release-coordination capability.
Central authority: Br174/Chatgpt.

PURPOSE
Make MotorLab release propagation part of the release transaction itself so registered projects cannot silently remain on an obsolete satellite while central MotorLab advances.

CORE RULE
A MotorLab release is not operationally COMPLETE until every registered project target is either:
- UPDATED_VERIFIED to the new release at a safe boundary; or
- PENDING_SAFE_BOUNDARY with exact repository/ref/reason recorded for automatic adoption at the next safe boundary.

TARGETS
- Every registered project default branch.
- Every explicitly registered/current active LAB/CANDIDATA/work ref.
- Future active refs discovered by Project Continuity before release closure.

SAFE-BOUNDARY GATE
Before mutating a project target:
- no active write/build/test/promotion must be running on that target;
- preserve project-native engine/lifecycle;
- preserve current verified local core as LAST_GOOD;
- never rewrite application/domain/runtime code as part of MotorLab-only synchronization.

FANOUT PAYLOAD
At minimum synchronize:
- .motorlab/MOTORLAB_BOOT_CAPSULE.txt (from central MOTORLAB_BOOT_CAPSULE_V1.txt)
- .motorlab/MOTORLAB_LOCAL_CORE.txt
- .motorlab/MOTORLAB_LOCAL_CORE_LAST_GOOD.txt
- .motorlab/MOTORLAB_SYNC_STATE.txt
- .motorlab/execution/motorlab_execution_fabric.mjs
- stable bootstrap/session-pin/re-entry adapter where supported
- .codex/hooks/motorlab_boot.py + .codex/hooks.json with UserPromptSubmit re-entry where supported
- Pollicino/Live-Control control-plane files required by the current release where supported

SESSION IMMUTABILITY
SESSION_RELEASE_PIN=required.
A session pins the full local MotorLab control snapshot at its first SessionStart.
Every supported UserPromptSubmit/resume/compact/clear re-enters MotorLab through the Re-entry Gate.
A newer release may be written to the repository while a session is open. The existing pin remains valid until a re-entry boundary.
At a re-entry boundary, a newer VERIFIED local satellite may refresh the pin when no explicit in-flight write/build/test/promotion lock is recorded; otherwise keep the current pin until safe.
Never downgrade or invent a release.

RELEASE TRANSACTION
1. PREPARE central release and tests.
2. Set FANOUT_STATE=IN_PROGRESS.
3. Discover registered default + active refs.
4. For each safe target, synchronize MotorLab control-plane payload and verify release markers.
5. For each busy target, write PENDING_SAFE_BOUNDARY into central/project continuity state; do not force a mid-operation switch.
6. Verify all safe targets and exact release ids.
7. Only then set FANOUT_STATE=COMPLETE and declare the MotorLab release globally adopted.

NO SECOND SCHEDULER
Release Fanout is release coordination, not a runtime scheduler. Velocity remains the sole runtime scheduler.

HOST LIMIT
This mechanism executes when an authorized MotorLab/GitHub release executor has an execution cycle. Repository text alone cannot wake a completely inactive host. Within a MotorLab release operation, fanout is mandatory and cannot be skipped silently.

R30 CAPSULE FANOUT
A target is not UPDATED_VERIFIED unless the local capsule exists, matches the central release, the bootstrap emits it before long-form detail, and the compact startup context remains below the declared host cap.

Revision 1.1: r30 adds the critical capsule to mandatory fanout verification.


R31 RE-ENTRY FANOUT
A target is not UPDATED_VERIFIED for r31 unless:
- local capsule/core declare r31 re-entry markers;
- motorlab_boot.py accepts UserPromptSubmit;
- hooks.json invokes motorlab_boot.py before Pollicino on UserPromptSubmit;
- a focused re-entry verification proves same-turn capsule reinjection and safe newer-local pin refresh;
- application/domain/runtime code remains unchanged.

Revision 1.2: r31 makes every-turn re-entry adapter/hook propagation part of release fanout verification.


R32 BUILD FAST LANE FANOUT
A target is not UPDATED_VERIFIED for r32 unless local capsule/core carry:
- BUILD_FAST_LANE=required;
- SAFETY_SOURCE_CHECKPOINT=github_immutable_ref;
- SAFETY_APK_MATERIALIZATION=on_demand;
- ARTIFACT_READY_DELIVERY=required.
Android project adapters are aligned at safe approved build-infrastructure boundaries; non-Android projects inherit the policy markers without application/runtime changes.

Revision 1.3: r32 adds deferred safety/build-fast-lane markers to mandatory fanout verification.
