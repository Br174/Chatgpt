# Pac-Man zero-cost approval alternative — LAB proposal
Status: **CANONICAL LAB PATH**. Cloudflare Access / Zero Trust is explicitly rejected for Pac-Man owner approval because the project requirement is €0. WebAuthn/passkey is the active authentication path. No production changes or live D1/GitHub mutations are authorized by this status.
## Goal
Avoid Cloudflare Zero Trust onboarding that requests billing authorization. Reuse existing staging Worker/D1 where supported by current free-plan quotas. No guarantee of zero cost without checking actual account usage and billing limits.
## Authentication
- Register one owner WebAuthn credential from an HTTPS origin controlled by the staging deployment. Challenge generated by server-side crypto, short-lived, random, bound to RP ID and origin; store public credential key and monotonic signature counter in staging D1 only after explicit approval.
- Registration requires a separately verified bootstrap of the real owner. A first-come-first-served registration URL is unsafe; chat consent alone cannot bootstrap identity. Bootstrap can use an existing independently authenticated account session or one-time in-person/out-of-band verification; do not invent this trust link.
- Each approval requires a fresh WebAuthn assertion over a server challenge bound to exact operation ID, LAB branch, path, capability, content digest and expiration. Validate origin, RP ID hash, challenge, signature, user presence and (if policy requires) user verification. Fail closed.
- Store and atomically consume a one-time approval claim before the existing issuer signs the exact operation; never accept a user-supplied attestation or WebAuthn JSON without verification.
## Constraints
- Existing PACMAN_* V2 runtime flags remain OFF. No changes to main/MADRE/production. No live GitHub writes, D1 writes or Worker deployment under this design approval.
- Evaluate WebAuthn library support in Cloudflare Workers, Android browser/passkey availability, HTTPS hostname/RP ID, attestation policy, recovery and lost-device process.
- Check Cloudflare Workers/D1 free-tier and account-specific billing terms before calling the solution zero-cost.
- Prevent public enrollment, replay, duplicate challenge consumption, CSRF, clickjacking, cross-origin approvals, credential replacement, and privilege escalation.
## Proposed incremental LAB tests
1. Verify challenge origin, RP ID, expiry, operation digest binding, and single-use nonce.
2. Verify signed assertion with fixture public key; reject replay, bad signature, counter regression and missing user verification.
3. Test enrollment bootstrap denial and lost-device recovery policy.
4. Integrate issuer with existing trusted-approval gate in disabled LAB-only mode.
## Explicit non-goals
No assumption that ChatGPT's chat buttons convey a cryptographically authenticated user identity; no automatic access to Android biometrics or passkeys from this conversation.
