UAB PROJECT ROUTING - MOTORLAB-CORE-V1.5

Purpose
Repository-specific adapter/routing state for the single MotorLab engine. No repository gets an independent lifecycle engine. All projects follow MADRE -> LAB -> CANDIDATA -> NEW MADRE using the atomic/exact-promotion method in UAB_UNIFIED_ENGINE_V1.txt.
Last verified: 2026-09-28.

GLOBAL SINGLE-CHAT PRINCIPLE
For every project, the chat in which Bruno initiates/continues that project task remains the canonical user-facing thread when a usable chat reference exists. Backend jobs may run on GitHub Actions, workers, runners or other durable executors, but Bruno must not be required to migrate manually to another conversation just because the executor changes.

GLOBAL ROUTING RULES
1. Re-check repository visibility before a build.
2. Public build projects -> standard GitHub Actions is default remote compiler/test runner and is a durable background executor for supported build/test phases.
3. Private build projects -> conserve included quota; no automatic paid fallback. Durable runner/local worker may be used only when adapter-approved and available.
4. Codemagic is REMOVED from MotorLab and must not be used as primary, fallback or emergency route.
5. If an allowed route is unavailable, stop and report the blocker rather than switching to an unauthorized provider automatically.
6. Project-specific workflows are adapters/mechanics only and cannot override lifecycle/promotion rules.
7. A normal ChatGPT turn alone is never considered a durable background route.
8. Background-capable work is routed proactively before a long foreground phase; do not wait for Bruno to leave the app.
9. Reopening the canonical project chat first reconciles active job/lock/checkpoint state before starting new writes.
10. Executor migration must not force routine user chat migration.

GLOBAL BACKGROUND RULE
1. Canonical user surface = current project chat.
2. Execution may move among adapter-approved durable executors behind the scenes.
3. While Bruno is away, a durable RUNNING job continues through approved autonomous steps and saves checkpoints.
4. Checkpoint is safety, not pause-on-exit.
5. If the executor stops/quota ends, continue from checkpoint on another approved route when safe; otherwise WAITING_EXTERNAL/WAITING_USER.
6. Never claim background continuity unless a real durable executor is active.
7. Detailed contract: MOTORLAB_BACKGROUND_EXECUTION_V1.txt.

GLOBAL EXACT-PROMOTION RULE
1. LAB = current MADRE + one requested modification (or one small inseparable change-set).
2. CANDIDATA = exact same MADRE + exact same approved LAB change-set, rebuilt fresh rather than renamed from LAB.
3. NEW MADRE source ref = exact approved CANDIDATA source SHA after explicit approval.
4. If this identity chain cannot be proven, promotion stops.

GLOBAL RELEASE RULE
Permanent Release = approved MADRE. LAB and CANDIDATA use temporary test artifacts. Never overwrite an existing MADRE release asset/tag. A latest pointer may identify the newest immutable MADRE but may not replace historical storage.

GLOBAL ENGINE RULE
All current and future projects follow MOTORLAB-CORE-V1.5 and UAB-ADAPTER-SPEC-V1.3. Any workflow that conflicts is legacy until aligned.

GLOBAL CACHE RULE
Persistent safe cache is mandatory where supported.

GLOBAL PROGRESS RULE
5/15/30/45/60/75/85/95/100 broad ladder plus verified micro-milestones and frequent status updates. Never report 100% before verification.
