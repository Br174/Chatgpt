GLOBAL ROUTING RULES
1. Re-check repository visibility before a build.
2. Public build projects -> standard GitHub Actions is default remote compiler/test runner.
3. Private build projects -> conserve included quota; no automatic paid fallback.
4. Codemagic -> verified-free emergency fallback only.
5. Project-specific workflows are adapters/mechanics only and cannot override lifecycle/promotion rules.

GLOBAL EXACT-PROMOTION RULE
1. LAB = current MADRE + one requested modification (or one small inseparable change-set).
2. CANDIDATA = exact same MADRE + exact same approved LAB change-set, rebuilt fresh rather than renamed from LAB.
3. NEW MADRE source ref = exact approved CANDIDATA source SHA after explicit approval.
4. If this identity chain cannot be proven, promotion stops.

GLOBAL RELEASE RULE
Permanent Release = approved MADRE. LAB and CANDIDATA use temporary test artifacts. Never overwrite an existing MADRE release asset/tag. A latest pointer may identify the newest immutable MADRE but may not replace historical storage.

GLOBAL ENGINE RULE
All current and future projects follow UAB-CORE-V1.1 and UAB-ADAPTER-SPEC-V1.1. Any workflow that conflicts is legacy until aligned.

GLOBAL CACHE RULE
Persistent safe cache is mandatory where supported.

GLOBAL PROGRESS RULE
5/15/30/45/60/75/85/95/100 default milestone ladder, recalculated when phases do not apply. Never report 100% before verification.
