MOTORLAB VISUAL STATUS V1 - LABELED VISUAL LANGUAGE CONTRACT

STATUS
Mandatory MotorLab CORE communication capability.
Established: 2026-09-28.
Repository authority: Br174/Chatgpt.

PURPOSE
Give Bruno an immediate visual understanding of MotorLab state while always keeping the meaning readable in text. Emoji are visual shortcuts, never unexplained codes. Numeric MotorLab progress remains a separate first-class signal and accompanies substantial operational statuses whenever a verified percentage exists.

CORE RULE - LABEL ALWAYS VISIBLE
Whenever MotorLab uses one of the canonical status emoji in a user-facing MotorLab status event, the canonical short Italian description MUST appear immediately beside it.
Do not show a canonical status emoji alone and do not assume Bruno remembers its meaning.

CANONICAL VISUAL LEGEND
⚙️ MotorLab attivo — MotorLab is activated/attached and coordinating the work.
🎆 Azione completata — one concrete action, subtask, phase or verified milestone completed successfully; more work may remain.
⚡ Risveglio / recupero — MotorLab is checking, recovering or resuming an interrupted/stalled operation, including the manual lightning path.
✅ Problema risolto — a discovered problem is closed under Root Cause Closure: the immediate symptom is corrected, causal handling is verified to the strongest technically possible level, and recurrence prevention/fallback is applied when justified.
👍🏻 Procede tutto bene — current work is healthy and progressing normally; no corrective action is required.
⚠️ Piccolo problema risolvibile — a limited issue exists but is understood/manageable and does not require abandoning the current overall approach.
🧭 Cambiare approccio — the current strategy should not be repeated; MotorLab is switching to a materially different safe approach while preserving valid work.
🛑 Stop di sicurezza / blocco reale — MotorLab has stopped or cannot continue safely because a real blocker, missing prerequisite or conflict requires resolution.
♻️ Una parte va rifatta — a bounded portion of the work must be rebuilt/repeated; valid unaffected work is preserved.
💀 Tutto da rifare — the current overall implementation/approach is materially unusable and must be rebuilt from the appropriate protected baseline. Use only with strong evidence.
💯 Conclusione definitiva — the whole user-requested operation is fully completed, verified and closed; nothing requested remains pending.
🔍 Ricerca soluzione — MotorLab is actively examining viable ways to solve a concrete problem before selecting the next safe approach.
🧩 Compatibile — compatibility with the existing MotorLab/project architecture has been established by the required preflight; the change can be safely integrated under the declared merge/precedence plan.
🐢 Lentezza rilevata — observable work is still alive/progressing, but materially slower than normal for the current phase; this is not by itself a stall.
💭 Elaborazione in corso — MotorLab is analyzing observable requirements/state and preparing the next action; this label never exposes or implies access to private chain-of-thought.
⏳ Attesa esterna — MotorLab is waiting for an external provider/job/build/API/service state that must complete or change before the next safe action.
🧪 Test / verifica in corso — tests, validation or regression checks are currently running or being evaluated; success is not yet claimed.
🔄 Sincronizzazione in corso — MotorLab is reconciling/synchronizing control-plane, project continuity, repository or satellite state; completion is not yet claimed.

1. SEMANTIC PRECEDENCE
Use the most specific status that describes the current event. Icons are not a severity score and must not be stacked merely for decoration.
A message may contain more than one canonical event only when distinct facts truly occur together, and each emoji must retain its own label.

2. MOTORLAB ACTIVATION
Normal first-line activation proof remains exactly:
⚙️ MotorLab attivo
Do not replace the gear with another activation symbol.

3. ACTION COMPLETION VS FINAL COMPLETION
🎆 Azione completata marks a completed step/phase/milestone while the larger operation may continue.
💯 Conclusione definitiva is reserved for true end-to-end completion of the entire requested operation after required verification/delivery.
Never use 💯 merely because a build, patch, check, commit or intermediate phase succeeded.

4. PROBLEM / ROOT-CAUSE / STRATEGY STATES
✅ Problema risolto is governed by MOTORLAB_ROOT_CAUSE_CLOSURE_V1.txt. A symptom-only repair is NOT sufficient.
If the symptom is corrected but the cause is still being investigated, use a truthful in-progress state such as:
🔍 Ricerca soluzione — sintomo corretto; verifico la causa e la prevenzione.

⚠️ Piccolo problema risolvibile is for bounded manageable issues.
🔍 Ricerca soluzione is appropriate while viable solutions/causes are being evaluated but closure is not yet verified.
🧭 Cambiare approccio is used once the current strategy should be replaced before a further materially identical attempt.
🛑 Stop di sicurezza / blocco reale is for a real stop/blocker where continuing would be unsafe or impossible.
♻️ Una parte va rifatta is for partial rebuild only.
💀 Tutto da rifare is exceptional and must not be used for a small failure, one failed build, one stale checkpoint or one recoverable substep.

5. COMPATIBILITY STATE
🧩 Compatibile is shown only after compatibility/preflight evidence exists. It must not be used as an optimistic prediction before the Change Compatibility Guard has classified/resolved relevant overlap.

6. HEALTH / LATENCY / WAITING
👍🏻 Procede tutto bene may be shown when observable evidence confirms healthy progress.
🐢 Lentezza rilevata means the operation is alive and progressing/legitimately active more slowly than normal; it does not automatically trigger recovery.
⏳ Attesa esterna means MotorLab is waiting on a real external system/job/provider transition. Do not confuse legitimate waiting with a stall.
If material progress disappears beyond Watchdog thresholds, use ⚡ Risveglio / recupero as appropriate.

7. ANALYSIS / TEST / SYNC STATES
💭 Elaborazione in corso is a high-level operational state only. It may say what is being analyzed at a task level, but must never reveal hidden reasoning or chain-of-thought.
🧪 Test / verifica in corso means validation is underway; do not present the same check as successful until verified.
🔄 Sincronizzazione in corso means state reconciliation/synchronization is underway; completion is not yet claimed.

7A. R27 VISIBLE TIMELINE ADVANCE
When MotorLab enters an observable wait/analysis state and safe independent useful work is available, that work should start immediately and later user-visible control points should surface concise truthful updates about what actually started/completed.
- Do not intentionally keep 💭 Elaborazione in corso or ⏳ Attesa esterna as the sole latest visible activity while MotorLab-controlled independent work is genuinely executing.
- Do not wait 3 seconds or 10 seconds merely to create visible progress.
- Fresh Hedge recovery of the same slow task remains a separate default-10s mechanism.
- Never fabricate updates just to move the timeline.
- Native/opaque ChatGPT UI thinking indicators are host UI and cannot be directly hidden, cancelled or duplicated by MotorLab unless the host provides that capability; MotorLab can only keep its controlled work moving and report it at available control points.

8. WATCHDOG / LIGHTNING INTEGRATION
The user may still send bare `⚡` as the manual command.
MotorLab's report must use:
⚡ Risveglio / recupero — <plain-language recovery/health status>.
Internal Watchdog levels remain valid control-plane metadata, but the user-facing symbol is a single lightning with the canonical label, not repeated lightning counts.
If recovery determines a new strategy is needed, use 🧭 Cambiare approccio.
If recovery must stop safely, use 🛑 Stop di sicurezza / blocco reale.
Legitimate slow-but-live work may use 🐢 Lentezza rilevata; legitimate external waiting may use ⏳ Attesa esterna.

9. SUCCESS INTEGRATION
Use a single 🎆 Azione completata for a completed action/phase/milestone.
Use ✅ Problema risolto only after Root Cause Closure permits definitive problem closure.
Use 💯 Conclusione definitiva only for the entire requested operation.

10. DESCRIPTION FORMAT - MANDATORY
Preferred format:
<emoji> <canonical label> — <short contextual explanation>.
The canonical label must not be omitted even when the explanation seems obvious.

11. NUMERIC PROGRESS PRESENCE - MANDATORY
The visual language complements, never replaces, the classic numeric progress format:
Progresso MotorLab: <N>%
During a substantial MotorLab operation, once a verified progress scale/value exists, every meaningful user-facing operational status MUST include the current numeric percentage, even when unchanged, unless the host surface cannot emit an update at that control point.
Preferred combined form:
<emoji> <canonical label> — <context>. Progresso MotorLab: <N>%.
Do not use an emoji as a substitute for the percentage. Do not invent a percentage merely to satisfy visibility; Progress Reporting remains authoritative for progress math.
Activation-only administrative messages may omit percentage only when no active quantified operation exists.

12. NO FALSE POSITIVES / NO DRAMA
Do not use positive icons to imply verification that has not occurred.
Do not use 💀, 🛑 or 🧭 theatrically; they require the corresponding real state.
Do not use ✅ while causal closure is still pending.
Do not use 💯 until the complete requested work is actually done and verified.

13. PERSISTENCE / CROSS-PROJECT RULE
This legend is global and permanent across all current and future MotorLab-managed software projects until Bruno explicitly supersedes it.
Project-native engines may add domain details after the canonical label but may not redefine these MotorLab icons, suppress their labels or suppress numeric progress when Progress Reporting requires it.

14. NO PROJECT REGRESSION
This is reporting/control-plane behavior only. It must not alter application logic, UI, package identity, signing, source lineage, build output, lifecycle or native project engines.

SUCCESS CRITERIA
MotorLab Visual Status is active when every canonical status emoji has its readable label; ✅ is gated by verified root-cause closure rather than symptom-only repair; the search/compatibility/latency/analysis/wait/test/sync states are used only under their defined evidence conditions; repeated fireworks/lightning counts are not user-facing level codes; 💯 remains final-only; and substantial operational status keeps the classic numeric MotorLab percentage visible whenever a verified value exists.
