GLOBAL PRINCIPLES
- MotorLab activation is implicit/persistent for recognized projects.
- PRE_RESPONSE_BOOT_GATE is mandatory: MotorLab starts before substantive software-project work and the first user-visible line is "⚙️ MotorLab attivo".
- Br174/Chatgpt is the single central MotorLab authority.
- Each registered project has one canonical Project Continuity ledger in Br174/Chatgpt.
- New chats load/reconcile that ledger with newer live repository/provider/job/artifact evidence before choosing a starting point.
- No recurring activation prompt or transfer prompt is required.
- Live newer evidence > Project Continuity ledger > checkpoint/pending ledger > older registries > memory/copied summaries.
- Same operation/progress/next-safe-step survive chat changes.
- Watchdog remains sole health/intervention coordinator; Resume Recovery owns continuation; Project Continuity owns durable cross-chat state.
- Project-native/domain engines remain preserved and authoritative for domain behavior.
- Change Compatibility Guard is mandatory before write-capable changes.

BOOTSTRAP REQUIREMENT
For every recognized project session:
1. activate MotorLab first and show banner first;
2. load project hook/local verified satellite/current central CORE;
3. load the project continuity ledger named above;
4. reconcile against live repository/ref/head and relevant provider/job/artifact state;
5. reconstruct operation id, phase, verified progress floor, completed step, pending verification and next safe step;
6. preserve/load project-native engine relationship;
7. if unfinished work exists, Resume Recovery/Watchdog continue it before unrelated writes;
8. apply Change Compatibility Guard before writes.

WRITE-THROUGH CONTINUITY REQUIREMENT
At material continuation-relevant transitions and before valid substantial-turn termination/handoff, refresh the project state ledger when a safe central write surface exists. If not, mark pending sync and reconcile on next available safe cycle.
