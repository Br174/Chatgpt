R11 PROBLEM-CLOSURE RULE
For a real defect/anomaly/stale state/unexpected trigger/failure:
1. contain/correct the immediate symptom safely;
2. determine why it occurred using evidence;
3. distinguish confirmed cause / leading hypothesis / external cause / unknown cause;
4. correct or contain the causal mechanism when possible;
5. inspect the smallest relevant recurrence surface;
6. add prevention/regression protection when justified;
7. do not use ✅ Problema risolto merely because a retry/restart/manual alignment worked once.
Root-cause/prevention work remains part of the operation and may keep progress below 100%.

R11 NUMERIC PROGRESS RULE
- classic format remains `Progresso MotorLab: <N>%`;
- after the activation banner, active/pending/new substantial work establishes/reconstructs and displays an evidence-based N% before long opaque execution;
- meaningful visible statuses carry the current N% when the surface permits;
- long provider/job phase changes repeat or advance N% rather than remaining silent;
- same N% may repeat; fake advancement is prohibited;
- new chat/turn does not reset/suppress same-operation verified progress.

R12 FAST ITERATION + NO-SPIN RULE
- persistent external work is handed off by durable job/run id + checkpoint + next-safe-step and the ordinary foreground chat must not poll indefinitely waiting for completion;
- default maximum is two consecutive unchanged foreground job-status probes after durable identity is established;
- eligible LOW/MEDIUM isolated LAB correction loops use risk-scaled verification rather than automatic promotion-grade full regression;
- HIGH-risk work and every CANDIDATA/MADRE promotion retain full applicable regression/lifecycle gates;
- later control cycles reconcile the recorded job id before any duplicate start/write;
- Fast Iteration coordinates Velocity/Foreground/Background/Watchdog/Resume Recovery without replacing their ownership.

SAFE ADOPTION RULE
Never force a future satellite release change into an active write/build/test/promotion operation. Pin the operation release and adopt a newer release only at a safe boundary under MOTORLAB_SATELLITE_SYNC_V1.txt.
For MotorLab-only metadata sync commits, use provider-supported CI suppression where safe/available; do not suppress CI when real app/source/config changes require validation.

FUTURE PROJECTS
Every future concrete software project receives hook + local satellite + central continuity ledger and inherits labeled visual status, hard numeric progress visibility, live-event classification, Root Cause Closure, safe control-plane CI suppression, Fast Iteration and No-Spin Handoff automatically. Where no project-specific risk map exists, verification remains conservative until actual project evidence supports a reduced LAB path.

HOST LIMITATION
Repository configuration cannot wake a host with no execution cycle. r12 therefore avoids depending on such a wake after durable handoff: persistent external jobs continue independently and are reconciled at the next available control cycle.
