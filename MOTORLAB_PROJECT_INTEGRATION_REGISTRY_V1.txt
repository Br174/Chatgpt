BOOTSTRAP REQUIREMENT
For every recognized project session:
1. activate MotorLab first and show banner first;
2. load project hook/local verified satellite/current central CORE;
3. load the mapped Project Continuity ledger;
4. reconcile against newer live repository/ref/head/provider/job/artifact state;
5. reconstruct operation id, phase, verified progress floor, completed step, pending verification and next safe step;
6. restore/preserve the project-native engine relationship;
7. if unfinished work exists, Resume Recovery/Watchdog continue it before unrelated writes;
8. apply Change Compatibility Guard before writes.

WRITE-THROUGH CONTINUITY
At material continuation-relevant transitions and before valid substantial-turn termination/handoff, refresh the project state ledger when a safe central write surface exists. A chat-id change never creates a new project operation by itself.

MUSICLAB R8 LIVE PROOF
Cross-chat write-through has been observed in real use: while another chat continued MusicLab LAB15, MOTORLAB_PROJECT_STATE_MUSICLAB_V1.txt advanced independently from the original seed to a newer head/run while preserving the 93% recovery floor. Subsequent readers must use that newer ledger/live state rather than the older bootstrap seed.

HOST LIMITATION
If the host exposes no project identity, persistent instruction, repository identity, conversational context or software-build intent, repository files cannot physically self-activate. Once a supported signal is exposed, pre-response activation and continuity reconciliation are mandatory.

NEW PROJECTS
Every future concrete software project receives project hook/local satellite, registry entry, central Project Continuity ledger, pre-response MotorLab boot gate and current CORE rules.
