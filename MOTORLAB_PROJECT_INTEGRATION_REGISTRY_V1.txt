R26 COORDINATED ADAPTIVE POLICY

- Default Fresh Hedge hard trigger: 10000 ms.
- Explicit material stall may trigger hedge recovery earlier.

- Write/integration duplication is forbidden.
- External/provider hedging requires explicit adapter authorization and External Service Guard compliance.
- Adaptive Lane Pool uses measured success/latency/throttle/saturation evidence and remains below global/provider/write-safety caps.
- Ordinary non-adaptive work retains the r25 fast path.

R27 CENTRAL ZERO-IDLE POLICY
- Independent compatible READY work is dispatched immediately; no artificial delay is added before useful sidework.
- Predeclared productive sidework may be spawned immediately when expected TTTA gain exceeds overhead.
- Same-task recovery remains a distinct path with a default 10000 ms hard trigger for eligible unresolved work.
- Controlled analysis/wait tasks may opt into replacePrimaryOnHardHedge: at the hard trigger the stale primary attempt is cancelled or invalidated and late results cannot win.
- Productive sidework and same-task recovery may overlap without adding a second scheduler.
- Visible activity reports only real started/completed work; host-limited execution remains explicitly reported.

R25 COMBINED SPEED POLICY
- First eliminate safely unnecessary work.
- Then reuse valid cache/checkpoints and reduce to invalidated deltas.
- Accelerate the intrinsic dispatcher hot path without changing semantics.
- Form named semantic workgroups only from remaining necessary independent work.
- Parallelize only when expected TTTA gain exceeds overhead/contention.
- Use r24 latency branching only after the above layers when a live task becomes slow.
- Preserve one scheduler (Velocity), one authoritative integration lane and all single-writer/project-native boundaries.

R24 LATENCY BRANCH POLICY
- When a live task crosses a declared latency threshold, preplanned independent useful work may start before the parent finishes.
- Trigger only when EXPECTED_GAIN_MS > OVERHEAD_MS.
- If the parent finishes first, cancel the trigger.
- Wake the dispatcher immediately when latency work is spawned.
- Never duplicate irreversible/costly provider side effects as a blind race.
- Preserve lock scopes, single-writer, runner caps and the single integration lane.
- Completion countdowns are never presented as guaranteed unless truly deterministic.
