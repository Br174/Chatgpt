GLOBAL PRINCIPLES
- MotorLab activation is implicit/persistent for recognized projects.
- Br174/Chatgpt is the only central authority; local satellites are synchronized mirrors, not forks.
- Project-native/domain engines remain preserved and authoritative for domain behavior.
- Change Compatibility Guard is mandatory before every write-capable MotorLab/project change.
- Watchdog is the single coordinator for progress-health detection and anti-stall intervention.
- Resume Recovery owns checkpoint continuation after Watchdog classification.
- Foreground Stall Guard owns prevention/chunking/durable handoff.
- Background Execution owns persistent executor/job semantics.
- Progress Reporting owns user-visible operational status.
- Preventive Watchdog health checks are required for substantial work when progress is unclear/repetitive and control/status evidence exists.
- After two materially identical no-progress write/retry/recovery attempts without new evidence, a third identical attempt is prohibited unless healthy external waiting is confirmed.
- User message `⚡` is the universal manual MotorLab health/recovery shortcut at the first available execution cycle; it never restarts completed work from zero.
- Automatic recovery remains mandatory and does not depend on the shortcut.
- MotorLab cannot force a new assistant turn while the host exposes no execution cycle.

BOOTSTRAP REQUIREMENT
Recognized project sessions use current CORE entrypoint. Before write-capable changes apply Change Compatibility Guard. Before risky/long work apply Foreground Stall Guard. During substantial work Watchdog may perform preventive progress-health checks. Interrupted work resumes through Resume Recovery.

MANUAL LIGHTNING REQUIREMENT
If Bruno sends only/primarily `⚡` and an execution cycle is available:
- inspect active/pending operation and latest checkpoint;
- verify current external/repository state;
- preserve completed work, percentage and writer lock;
- Watchdog classifies health;
- Resume Recovery continues the smallest safe pending step if needed;
- do not restart from zero or duplicate healthy external work.
If no pending operation exists, report that rather than inventing one.

PROGRESS VISIBILITY
Substantial work should provide concise live-like operational status when possible, normally after roughly 1-2 meaningful operations or material phase/status transitions. Report observable actions/results, not hidden chain-of-thought. Verified percentages never advance from elapsed time alone.

HOST LIMITATION
If ChatGPT/the host is fully suspended and provides no execution cycle, MotorLab cannot inject a lightning message or make a user `⚡` message execute until the host accepts/delivers it. Checkpointing, persistent executors and first-available-cycle recovery reduce the impact but do not bypass this platform boundary.

NEW PROJECTS
Every future MotorLab software project receives the current satellite/hook during onboarding when technically available and inherits Change Compatibility Guard, preventive Watchdog, manual `⚡`, two-strike anti-loop, Resume Recovery, Foreground Stall Guard and all other current CORE protections.
