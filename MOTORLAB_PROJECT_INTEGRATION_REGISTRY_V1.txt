PURPOSE
Track which project repositories are structurally connected to MotorLab and which contain the local-first synchronized satellite defined by MOTORLAB_RELEASE_MANIFEST_V1.txt and MOTORLAB_SATELLITE_SYNC_V1.txt.

GLOBAL PRINCIPLES
- MotorLab activation is implicit and persistent for recognized registered projects.
- MOTORLAB_PROJECT_HOOK.txt is the project identity/adapter entrypoint.
- .motorlab/MOTORLAB_LOCAL_CORE.txt provides immediate verified local activation/fallback.
- .motorlab/MOTORLAB_LOCAL_CORE_LAST_GOOD.txt provides rollback safety.
- .motorlab/MOTORLAB_SYNC_STATE.txt records local release and verification state.
- Br174/Chatgpt remains the only central authority; local satellites are synchronized mirrors, not forks.
- Project-native/domain engines are preserved and coexist with MotorLab.
- Change Compatibility Guard, visible session boot proof, verified progress reporting, Watchdog, Resume Recovery, Foreground Stall Guard, checkpoint recovery, single-writer protection and fireworks-success reporting remain mandatory when applicable.
- Before every write-capable MotorLab self-change or project change, Change Compatibility Guard must inspect current relevant state for conflicts, overlaps, duplicated responsibility, precedence ambiguity, protected behavior, blast radius, backward compatibility and regression risk.
- Overlaps must be integrated/merged or given explicit precedence/supersession before the write; unresolved unsafe conflicts block the write.
- MotorLab release changes occur only at safe boundaries, never in the middle of an active write/build/test/promotion operation.

BOOTSTRAP REQUIREMENT
Recognized project sessions should use MOTORLAB_CORE_ENTRYPOINT_V1.txt. The verified local satellite is available first; central release comparison/synchronization occurs at the first safe boundary. Current central CORE remains authoritative whenever reachable.
Before the first write-capable change, MOTORLAB_CHANGE_COMPATIBILITY_GUARD_V1.txt must analyze compatibility/conflict/overlap/regression risk and resolve any non-clear relationship.
Before substantial execution, MOTORLAB_FOREGROUND_STALL_GUARD_V1.txt must classify foreground risk and prepare checkpoint/durable execution state as applicable.

VISIBLE BANNER REQUIREMENT
Under normal successful activation, the startup proof is exactly:
⚙️ MotorLab attivo
Do not append satellite, CORE, synchronization or native-engine wording unless reporting a real warning, recovery event or blocker.

CHANGE COMPATIBILITY REQUIREMENT
This requirement applies both to MotorLab itself and to every present/future MotorLab-managed project. It is not optional project advice. A low-risk/atomic change may use a concise preflight, but the preflight may not be skipped.
If a new feature overlaps an existing mechanism, prefer extending or merging the existing responsible mechanism. If both must remain, define explicit precedence. If the old path must stop, supersede it explicitly rather than leaving duplicate active behavior.

FOREGROUND STALL REQUIREMENT
A ChatGPT client "still processing" message, spinner or elapsed time is not a MotorLab heartbeat. Long/backgroundable phases should be checkpointed and handed to a real persistent executor when one is safely available. If work must remain in ordinary chat, use bounded recoverable segments. If host execution disappears, Resume Recovery resumes at the first later available cycle and a lightning event is shown when MotorLab actually performs recovery.

HOST LIMITATION
A repository cannot force a context-free or completely frozen host/model to open a new execution cycle. Foreground Stall Guard is preventive and Resume Recovery acts at the first later available cycle; neither claims to awaken a suspended host independently.

NEW PROJECTS
When a future software project becomes concrete and repository integration is available:
- register it in canonical routing/integration state;
- install MOTORLAB_PROJECT_HOOK.txt;
- install .motorlab/MOTORLAB_LOCAL_CORE.txt from the current canonical bundle;
- install an identical initial .motorlab/MOTORLAB_LOCAL_CORE_LAST_GOOD.txt;
- install .motorlab/MOTORLAB_SYNC_STATE.txt as VERIFIED for the current release;
- bind MOTORLAB_CORE_ENTRYPOINT_V1.txt, release manifest and sync protocol;
- inherit MOTORLAB_CHANGE_COMPATIBILITY_GUARD_V1.txt before all write-capable changes;
- inherit MOTORLAB_FOREGROUND_STALL_GUARD_V1.txt;
- preserve all project-native engines;
- require visible activation proof and all current MotorLab CORE protections.
